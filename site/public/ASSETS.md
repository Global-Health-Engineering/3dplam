# Site assets

Everything here is committed and served directly. Scripts in `tools/`
regenerate the renders and figures. The photographs and video are supplied.

## photos/ (photographs of the printed device)

| File | Shows | Source |
|---|---|---|
| `manifold-assembled.webp` | Assembled manifold, printed in rPET | supplied |
| `manifold-in-use.webp` | Loaded membrane and syringe attached, mid-filtration | supplied |
| `base-with-filter-support.webp` | Base with the strand-mesh filter support seated | supplied |
| `filter-support-strand-mesh.webp` | Strand-mesh filter support close up, in-air printed strands visible | supplied |

The photos were converted from PNG to WebP at quality 82 and resized for web (17 MB → 0.8 MB).

## video/

| File | Shows |
|---|---|
| `base-printing-timelapse.gif` | Timelapse of the final base (V1.3) printing in rPET. 800 × 493, 115 frames, 11.5 s at 10 fps, 9.4 MB. Author-supplied; loops without interaction |

`Print.astro` embeds the GIF with a plain `<img>` element. The GIF loops
on its own, so it needs no controls, third-party player or external
hosting.

## models/ (regenerated by `tools/render_parts.py`, requires Blender)

These are glTF binaries for the click-to-open 3D viewer in `Device.astro`.
They are exported from the same Blender scene as the matching
`renders/*.png`, so each part has the same colour and shape in both. Each `.glb` pairs with the
render of the same name.

| File | Triangles | Size |
|---|---|---|
| `assembly-exploded.glb` | 106 k | 2.2 MB |
| `membrane-clamp.glb` | 115 k | 2.9 MB |
| `filter-support-section.glb` | 51 k | 1.4 MB |

The base arrives from CAD at 362 k triangles, which is too heavy to ship.
After the render is made, `render_parts.py` reduces the base to a 60 k
budget for the web copy only. Planar dissolve does most of that reduction
(362 k → 147 k). The silhouette does not change, because the removed edges
lay inside flat regions. Collapse decimation covers the rest.

The `.glb` files are fetched only when a reader clicks a render, never on
page load. They therefore do not affect how fast the page opens.
